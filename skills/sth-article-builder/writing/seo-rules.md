# SEO 核心規則摘要

> 範例沿用拜拜日曆（天赦日），換站時規則照用、範例只當示意。站點專屬的程式行為（例如由 `### Q：` 自動產生 schema）寫在站設定的 publish notes。

---

## 標題（Title Tag）

- 長度：中文約 15-30 字（其他語言看語言包）
- 主關鍵字自然放在標題前半段
- 讓人一看就知道「這篇能幫我什麼」
- 避免標題黨、誇張聳動、與內容不符的承諾

## Meta Description

- 長度：中文約 60-80 字（站設定 `frontmatter.excerpt_length` 可改；其他語言看語言包）
- 包含主關鍵字，讀起來是自然語句
- 當成廣告文案寫——決定讀者要不要點進來

## URL 結構

- 簡潔、有描述性
- 使用連字號 `-` 分隔，避免底線 `_`

## 標題層級

```
H1：文章主標題（每頁僅一個）
  H2：主要段落標題
    H3：子段落標題
```

- H2/H3 要具描述性，掃一眼目錄就知道全文在講什麼
- 自然融入語意相關詞，絕不堆砌

## FAQ 格式

> **為什麼還要寫 FAQ**（2026-08 更新）
> Google 已於 2026-05-07 停止顯示 FAQ 複合式結果，6 月退掉 Search Console 報表，8 月移除 API 支援。
> **寫 FAQ 的理由不再是搶 SERP 版位**，而是這兩件事：
> 1. FAQ 是 AI Overviews 與 ChatGPT / Perplexity 最容易擷取引用的區塊
> 2. 讓長尾問句在頁面上有明確落點，讀者掃一眼就找得到答案
>
> 格式規則照舊。`### Q：` 這個寫法仍然要維持。例：拜拜日曆的程式端 `extractFAQFromContent()` 靠它自動產生 FAQPage schema；其他站看站設定的 publish notes 有沒有類似機制。
> 該 schema 留著不會被懲罰，Google 明說未被使用的結構化資料不影響搜尋。

```markdown
## 常見問題

### Q：天赦日可以拜祖先嗎？

可以。天赦日主要是向天公祈求赦罪，但同時也適合祭拜祖先...

### Q：天赦日拜拜要準備什麼金紙？

天赦日拜天公需準備天金、壽金...
```

- 每個 QA 獨立成段，問題要是使用者會實際搜尋的自然語句
- 每篇文章至少 3-5 個 FAQ

## 步驟流程格式

- 每步驟用數字編號 + 粗體小標題 + 說明
- 步驟要有明確的先後順序

> **不要用 `### 步驟一：` 這種 h3 寫法。**
> 例：拜拜日曆的程式端 `extractHowToSteps()` 會據此自動產生 HowTo schema，而 Google 在 2023 年 9 月就已移除 HowTo 複合式結果。
> 用數字編號加粗體小標題不會觸發，可讀性也一樣好。

## 內部連結策略

### Topic Cluster 架構

```
Pillar Page（高權重）← 所有 Cluster 文章的連結匯聚於此
  ↓
Cluster 文章（分散權重）← 彼此水平互連，共同支撐 Pillar
```

### 連結數量標準

| 連結方向 | 數量標準 | 硬/參考 |
|---|---|---|
| Cluster → Pillar | **至少 1 個**，建議 2-3 個 | Pillar Page 已上線（有網址）時，至少 1 個是硬條件；還沒上線就不連，報告提醒上線後補。2-3 是參考 |
| Cluster ↔ Cluster | 同 Pillar 下互連 1-3 個 | 參考 |
| 跨 Pillar 連結 | 0-2 個 | 參考 |
| 整體密度 | 每 1,000 字 3-5 個內部連結 | 參考 |

> 站的 keyword plan 有自己的規格時以站的為準（格式見 `~/.claude/skills/keyword-plan/format.md` 的頁面規格）。
> 規格分成硬條件與參考值：0 條連回支柱頁是結構斷裂，屬硬條件；條數多寡只是參考，不判定對錯。
> 站沒有 keyword plan（沒有 pillar）時，Cluster → Pillar 這條不適用，報告標 ⚠️。

### Anchor Text 規則

- 用描述性關鍵字，禁止「點這裡」「看更多」
- Cluster → Pillar 帶入 Pillar 主關鍵字
- 同一篇中多個連向同頁面的連結，anchor text 要略有變化

### 連結位置

| 位置 | 建議連結類型 |
|---|---|
| 文章前段（前 30%） | Pillar 連結（Google 給較高權重） |
| 文章中段 | Cluster 水平連結 |
| 文章結尾 | Pillar 連結 + 延伸閱讀 |

### 外部連結

- 連結到可信賴的權威來源
- 每篇文章 2-3 個權威外部連結

## 自檢表

```
Frontmatter
[ ] 文章開頭 YAML frontmatter 齊全（欄位照 profile.frontmatter.fields；預設 title / slug / date / modified / status / excerpt）

標題與 Meta
[ ] 標題含主關鍵字，不聳動
[ ] Meta Description 60-80 中文字（或 profile.frontmatter.excerpt_length），含主關鍵字
[ ] URL 簡潔有描述性
[ ] H1 僅一個，與標題一致
[ ] H2/H3 結構清晰，盡量寫成完整問句
[ ] 每個次要關鍵字至少對應一個 H2 或 H3

內容品質
[ ] 開頭 2-3 句直接回答核心問題
[ ] 首段 100 字內自然帶出主關鍵字
[ ] 主關鍵字全文出現 3-6 次
[ ] 次要關鍵字各在對應段落出現 1-2 次
[ ] 有 FAQ 段落（至少 3 題，理由是 AI 引用與讀者查找，不是 rich result）
[ ] 流程類內容使用編號步驟格式，未使用 `### 步驟X：` h3 寫法

連結與媒體
[ ] 1-2 個連回 Pillar Page 的內部連結（Pillar Page 已上線時才檢查）
[ ] 1-3 個同 Pillar 下相關 Cluster 連結
[ ] 2-3 個權威外部連結
[ ] 圖片有 alt text

可讀性
[ ] 段落簡短，有使用清單/表格/粗體
[ ] 沒有關鍵字堆砌
[ ] 讀起來通順自然
```
