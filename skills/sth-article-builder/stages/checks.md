# 機器閘門：S9（硬性）

> 來源：拜拜日曆 auto-article S9、§6（全文）；人工檢查清單來自 plan-v5 §6。
> 拜拜專屬的農曆雙來源檢查移到拜拜的站設定 `extensions/lunar-date-check.md`；破折號、中英空格移到語言包。

**不通過就不上稿。**

原則：**有安全落點的自動處置，沒有落點的才 abort。**

## 通用檢查

| 檢查項 | 方法 | 不通過時 |
|---|---|---|
| 帶引號的引文 | 抓全文所有引號內的引文（中文 `「...」`，其他語言看語言包），逐條回原始 URL **字串比對** | 自動降級為描述式（去引號、改成指名書名的敘述） |
| 內部連結 | 草稿裡每個內部連結都要在 `{站}/content-inventory.csv` 的網址欄找得到。讀網站的細節（要不要帶 UA、哪些方法會被擋）照 `profile.adapters.read_source.website.notes`。**NEVER 用 HTTP 200 判斷頁面存在**（例：拜拜日曆未發布頁也回 200） | 清單涵蓋狀態是「已確認完整」或「只收本系統」→ 自動移除該連結（「只收本系統」是使用者選的範圍，清單外的頁一律不連）。「未確認」「失敗」→ 不直接刪：打開那個網址，確認是正常文章就保留；打不開才拿掉；判斷不了的列進人工檢查清單 |
| frontmatter | 解析 `profile.frontmatter.fields` 每個欄位 | 自動補齊 |
| 主關鍵字次數 | 檢查**必要位置**（Title／H1／URL／excerpt／首段 100 字／中段／結論）是否全中。`keyword-layout.md` 的「全文 3-6 次」**不適用於主題詞本身就是主關鍵字的認識篇**（例：一篇談灶神的長文必然出現數十次），該條僅用於防堆砌 | 必要位置有缺才回 S6 |
| 語言包檢查 | 照 `~/article-engine/language/{language}.md` 的「S9 檢查」逐項跑（例：zh-TW 的破折號「——」、中英文空格） | 照語言包寫的自動處置 |
| 導流連結 | `profile.site.cta.url` 有填時，文末行動呼籲在、連結正確 | 自動補上 |

## 站的擴充檢查

`profile.extensions` 裡 `hook: s9-check` 的每一項，讀 `{站}/extensions/{file}` 照做。擴充回傳三種結果之一：

| 結果 | 處置 |
|---|---|
| 放行 | 繼續 |
| 自動修 | 照擴充寫的修法改，記進報告 |
| 中止 | abort（見下） |

（例：拜拜日曆的農曆日期雙來源檢查，日期是生日型文章的核心，無安全落點，不一致就 abort。）

## 人工檢查清單

S7 記在 `manual_checks` 的論斷（推算型沒有擴充檢查、或規則判斷不了的），加上本步驟判斷不了的內部連結，轉成白話人工檢查清單，寫進最終報告：

```
## 要你親自確認的地方（打勾才算通過）
- [ ] 第 3 段「同花對上順子的機率約 X%」：這是推算出來的數字，目前沒有自動驗算
- [ ] 內部連結 /blog/xxx：清單裡找不到，網址打得開但判斷不了是不是正式文章
```

- 使用者打勾才算通過；**AI 不能自己宣告通過**。
- 有人工檢查項時照常上草稿（草稿本來就還沒發布），報告最上面標 ⚠️「有 N 項要你確認」。

## abort 時

**不上稿**，保留所有本地產物，報告說明卡在哪一項。
