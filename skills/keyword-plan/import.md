# 匯入既有的關鍵字規劃


## 步驟

1. **收檔**：使用者給的檔案（md、csv、xlsx 轉成 csv、Google Sheet 匯出）。沒給就先到 profile 的 `workspace.resources` 列的資料夾找看起來像關鍵字表的檔，列成候選問；都沒有再問路徑。
2. **先問哪個是最後產出物**：給了多個檔，而且內容有重疊（例：一份是查量總表、一份是主題規劃）時，列出每個檔的修改日期、列數、看起來是什麼，問「以哪一份為準？其他的當補充」。
3. **原樣複製**到 `{站}/keyword-plan/_source/`，之後只讀副本。
4. **讀全文、找出結構**：
   - 有哪些表格，每張表的欄位是什麼
   - 哪一欄是詞、量、日期、主題、主關鍵字、次要關鍵字、網址、狀態
   - 看不出來的欄位列給使用者確認（「第 3 欄『俗稱量』要當成另一個詞的量嗎？」）
5. **轉成新格式**（[format.md](format.md)）：
   - 主題（pillar）：來源有主題分類就照用；沒有就照 create.md 的分群規則提議，給使用者確認。
   - 子頁：來源有「文章」或「頁面」層級就照用；只有詞沒有頁 → 每個主題底下照意圖分群（create.md 第 4 步）。
   - 量：照抄，`source` 填 `import:{檔名}`，`volume_type` 依來源判斷（看到區間就填區間）。
   - 日期：來源有就照用；沒有就用檔案修改時間，`date_estimated: yes`。
6. **列出衝突**給使用者看，一次問完：
   - 同一個詞在不同檔的量不同 → 用哪個
   - 同一個詞歸到兩個主題 → 歸哪個
   - 來源的狀態跟網站對不上（來源寫已上線，網站清單找不到）→ 照網站，標「未確認」
7. **對到現有文章**：SKILL.md §3。
8. **行數核對**：來源裡每一個詞都要出現在 keywords.csv。少了就找出是哪些、為什麼，補回來；真的不收的（例：來源自己標了刪除）列給使用者確認。核對結果寫進 `{站}/keyword-plan/_source/import-log.md`。
9. 寫檔，印摘要：幾個主題、幾個子頁、幾個詞、幾個推定日期、幾個衝突怎麼處理的。

## 來源欄位跟 sth-article-builder 的關係

來源裡有、但 format.md 沒有對應欄位的資訊（例：拜拜日曆總表的「相關詞前 4」「頁面規格標準」），**不丟**：

- 是詞 → 進 keywords.csv（相關詞也是詞）。
- 是規則（例：連結數量規格）→ 寫進該主題檔最下面的「來源規則」段，原文照抄；跟 format.md 頁面規格不同時，在 `{站}/writing-guide.md` 提醒一句以哪個為準（問使用者）。
