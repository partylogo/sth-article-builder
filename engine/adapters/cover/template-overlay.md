# 封面：模板疊字（固定底圖＋主副標）

> 腳本、底圖、放字區域、字色、輸出目錄、字數上限、主標樣板從 `profile.adapters.cover.template_overlay` 讀；表格裡的例子是拜拜日曆的設定值。
> 設定精靈（第 7 段）設定的站一律用引擎內建的壓字程式 `scripts/overlay.py`，底圖是使用者給的或 `bases/` 的內建底圖。之前設定、用站自己腳本的站照舊能用。
> 「產圖後：檢查 WordPress 封面圖」搬到發佈平台轉接器的「設封面」動作（`adapters/publish/wordpress.md`）。

## 能力宣告

| 項目 | 值 |
|---|---|
| 輸入 | 主標＋副標，或文章（由 AI 提案主副標） |
| 輸出 | 一張 jpg，像素風格每次一致 |
| 成本 | 0（本機腳本） |

## 工具與腳本

| 項目 | profile 欄位 | 例：拜拜日曆 |
|---|---|---|
| 生成腳本 | `script` | 內建：`~/article-engine/adapters/cover/scripts/overlay.py`；站自己的腳本也可以（例：`~/banner-maker/make_banner.py`） |
| 底圖（固定） | `base_image` | `~/banner-maker/base.jpg`；內建底圖在 `~/article-engine/adapters/cover/bases/` |
| 放字區域 | `box` | `[72, 121, 672, 433]`（只有內建程式用；空的話程式自己找） |
| 字色 | `color` | `#ffffff`（只有內建程式用；空的話依底圖亮度選） |
| 上下位置 | `valign` | `middle`（只有內建程式用；top／middle／bottom） |
| 品牌 logo | `logo` | `/Users/…/logo.png`（只有內建程式用；空的話不放） |
| 預設輸出目錄 | `output_dir` | `~/banner-maker/output/` |
| 主標字數上限 | `title_max_chars` | 8 |
| 副標字數上限 | `subtitle_max_chars` | 22 |

- 內建程式：放字區域、字色寫在 profile，字級依底圖高度算，字型自動找系統的中文字型（PingFang、黑體、Noto Sans CJK、微軟正黑體）。
- 站自己的腳本：樣式（字型、品牌色、字級、座標）寫在腳本常數區，**不要在 skill 內改樣式**；要改就編輯腳本本身。

## 在 /sth-article-builder 流程裡（S11）

主副標照 `stages/publishing.md` 的封面規則生成：

- **auto 模式**：照主標樣板與副標規則直接生成一組，不提案不詢問 → 走「字數檢查」（auto：自動縮寫）→「執行產圖」。
- **互動模式**：走下方 Mode B 的提案（3 案）→ 使用者選 →「字數檢查」→「執行產圖」。

## 單獨使用（`/sth-article-builder cover <輸入>`）

判斷模式：

- **含「|」**（例：`什麼是錢母？ | 錢母怎麼求，可以花嗎，放那裡一次搞清楚`）→ **Mode A：直接產圖**
- **不含「|」**（例：`認識太陽星君`）→ **Mode B：先提案、確認後產圖**
- **空白** → 詢問使用者要哪種模式、給什麼內容

### Mode A：直接產圖

1. 切分輸入，取「|」左邊為主標、右邊為副標，兩邊都 `strip()`
2. 走「**字數檢查**」（見下方共用步驟）
3. 走「**執行產圖**」

### Mode B：提案 → 確認 → 產圖

1. 拿到文章名稱後，依下列**優先順序**找對應的文章來參考：
   1. **最新已發布文章**：在 `{站}/content-inventory.csv` 用標題找，照網址用讀取來源轉接器「抓回」。有就用這份，這是最新、最準的版本
   2. **草稿**：`{站}/runs/*/draft.md` 用標題或 slug 找。沒有已發布版本時才退而參考草稿
   3. 都沒有 → 純粹根據文章名稱發想
   找到後讀過去，理解文章重點再發想；找到已發布版本就**不要**再回頭用草稿。
2. **產出 3 個方案**，每個方案包含一組「主標 + 副標」。方案之間要有角度差異（例如：解釋型 / 帶問題勾子 / 條列承諾），不要 3 個都很像。
3. 主標字數 **≤ `title_max_chars` 字**、副標字數 **≤ `subtitle_max_chars` 字**（含全形標點各算 1 字）。超過容易壓到圖上的元素（例：拜拜日曆的底圖會壓到右側植物）。
4. 用 `AskUserQuestion` 列出 3 案，讓使用者選一個。每個選項的 label 用「主標 / 副標」格式，description 簡述這個切法的角度。
5. 使用者選定後 → 走「**字數檢查**」→「**執行產圖**」

## 共用步驟

### 字數檢查

- **內建程式**：不數字數，直接跑 `python3 {script} --base … --box … --title … --subtitle … --check`。回傳碼 0＝放得下；2＝放不下，照下面處理。`title_max_chars` 只在提案時當參考（英文、數字比中文窄，中英混排的標題可以比這個數字長）。
- **站自己的腳本**：主標 > `title_max_chars` 字 或 副標 > `subtitle_max_chars` 字時：
  - 互動或單獨使用 → 警告使用者「可能會壓到圖上的元素（例：右側植物），是否仍要繼續？」使用者堅持繼續才執行；想改就回到提案/輸入。
  - auto 模式 → 自動縮寫至上限內，不問（gate `cover-overflow`）。

### 執行產圖

1. 由主標推導檔名：
   - 移除標點符號：`？！。，、：；「」『』（）.,!?:;`
   - 移除頭尾空白
   - 範例：`什麼是錢母？` → `什麼是錢母.jpg`
2. 完整輸出路徑：`{output_dir}/{清洗後檔名}.jpg`
3. **檔案已存在處理**：先檢查路徑是否存在；若存在：
   - 互動或單獨使用 → 問使用者「覆蓋」「加 -v2 後綴」「取消」
   - auto 模式 → 一律加 `-v2` 後綴，**永不覆蓋**（gate `cover-exists`）
4. 執行：

```bash
python3 {script} \
  --title "<主標>" \
  --subtitle "<副標>" \
  --out "<完整輸出路徑>"
# 內建程式另外加：--base "{base_image}"；有值的才加：--box "x,y,w,h" --valign {valign} --color "{color}" --logo "{logo}"
```

內建程式回傳碼：2＝字放不下（照「字數檢查」縮寫後重跑）；3＝輸出檔已存在（照第 3 步處理）。

5. 用 Read 工具開啟產出的 jpg 給使用者看（auto 模式只在報告附路徑）
6. 回報檔案絕對路徑，寫進 state.json 的 `cover.file`
7. 接著走發佈平台轉接器的「設封面」動作（平台不支援就只交付圖檔）

## 不該做的事

- 不要直接生 AI 圖（這個工具是「固定底圖疊字」，每次必須像素一致）
- 不要改站自己腳本內的樣式常數（字型、顏色、座標、字級），除非使用者明確要求調整樣式；內建程式的位置與字色改 profile，不改程式
- 不要在沒確認的情況下覆蓋既有檔案
- 單獨使用的 Mode B 不要省略 3 案提案直接做圖：提案讓使用者選是這個模式的核心價值
